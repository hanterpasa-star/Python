# Бот наличия обуви для сотрудников

Закрытый Telegram-бот на Python. Владелец выдаёт доступ сотрудникам, сотрудники добавляют фото моделей и изменяют размеры. Все работают с одним каталогом через свои аккаунты Telegram — с телефонов, планшетов и компьютеров.

Для постоянной работы на отдельном Linux-сервере подготовлены [Docker Compose и инструкция переноса](deploy/CLOUD.md). Список реализованных выбранных функций хранится в [ROADMAP.md](ROADMAP.md).

## Что умеет

- Каталог с фото, размерами и количеством пар; поиск по названию, размеру и номеру товара.
- Разделы по брендам / типам обуви. Внутри товары по алфавиту; кнопка «Сортировка» позволяет выбрать новые товары или наименьший доступный размер.
- Продажи с корзиной из нескольких моделей и размеров. Цена вводится за одну пару в гривнах, остатки списываются после подтверждения.
- Частичный возврат по исходной цене и отмена ошибочной продажи с восстановлением остатков.
- Отчёты за день, неделю, месяц и выбранные даты: пары, выручка, возвраты, популярные модели и размеры.
- Вечерний отчёт владельцу в 21:00 по Киеву. Время меняется в боте.
- Автоматические резервные копии; владелец может получить копию в Telegram.
- Запрос доступа с кнопками владельца «Разрешить» / «Отказать»; ручные `/grant` и `/revoke` тоже работают.
- Уведомления об изменениях и последней паре / закончившемся размере; предупреждение перед добавлением модели с таким же названием.
- Товар добавляется обычным способом: название → фото → размеры. QR-коды и штрихкоды удалены по просьбе владельца.
- История изменений, статус устройства, защита от одновременных правок и повторного сохранения продажи.
- Подготовлен автозапуск Windows после входа в учётную запись и восстановление после сбоя.

## Обновление уже работающего бота

Сначала прочитайте короткую [инструкцию обновления](UPDATE_RU.txt). Новый архив не содержит вашего `.env` или базы. Скопируйте его файлы в прежнюю рабочую папку, сохранив свои `.env` и `data`. Не создавайте нового бота у BotFather.

При первом запуске с существующим каталогом создаётся копия старой базы в `data/backups/before-upgrade-…sqlite3`, затем добавляются новые таблицы и поля. Товары, фото, сотрудники, история и очередь уведомлений сохраняются. Для нестандартного `DATABASE_PATH` копии находятся рядом с базой в папке `backups`.

## С чего начать — Windows

1. Получите файлы проекта и распакуйте в постоянную папку, например `C:\shop-bot`. Не запускайте файлы прямо внутри ZIP.
2. Установите **Python 3.12** с [python.org](https://www.python.org/downloads/). При установке включите **Add Python to PATH**. Рекомендуется Windows 10/11 и Python 3.12 (64-bit); запуск также проверяется с 32-битным Python 3.12. Проверки выполняются также на Python 3.10. Windows 7 для этой версии не подходит.
3. В Telegram откройте официального **[@BotFather](https://t.me/BotFather)**. Отправьте `/newbot`, задайте название и username, заканчивающийся на `bot`. Он выдаст токен — ключ управления вашим ботом.
4. Дважды нажмите **`EDIT_SETTINGS.bat`**. Откроется файл `.env` в Блокноте. Если файла ещё нет, он будет создан; существующие настройки сохранятся.
5. В строке `BOT_TOKEN=` вставьте токен после знака `=`. Пока оставьте `OWNER_ID=` пустым. Сохраните файл и закройте Блокнот. Токен не публикуйте и не отправляйте в чаты.
6. Дважды нажмите **`START_BOT.bat`**: установятся зависимости и запустится бот. Оставьте окно запуска открытым. Найдите созданного бота в Telegram и отправьте ему **`/id`**. Он покажет ваш числовой ID.
7. Остановите бота клавишами **Ctrl+C**. Снова откройте **`EDIT_SETTINGS.bat`**, вставьте полученное число после `OWNER_ID=`, сохраните файл.
8. Снова запустите **`START_BOT.bat`** и отправьте своему боту **`/start`**. Теперь вы владелец и видите меню магазина.

Если `.env` уже существует, скрипты его сохраняют. Открыть его можно через `EDIT_SETTINGS.bat` или «Открыть с помощью → Блокнот». Имя файла должно быть `.env`, а не `.env.txt`: в Проводнике включите показ расширений файлов.

Если окно Windows сообщает об отдельных обрезанных командах вроде `'cho'`, `'error'` или `'T_TOKEN'`, обновите `START_BOT.bat` из исправленного архива. Windows-файлы запуска хранятся с окончаниями строк CRLF и командами ASCII, чтобы CMD не искажал их при чтении. При обновлении сохраняйте свой `.env` и папку `data`.

Пока `OWNER_ID` не заполнен, бот никому не показывает товары и позволяет только узнать свой ID. Первый открывший бот не становится владельцем автоматически.

## Как выдать доступ сотруднику

1. Сотрудник открывает вашего бота, отправляет `/start` и нажимает **«Запросить доступ»**.
2. Вам в личные сообщения приходит его имя и ID с кнопками **«Разрешить» / «Отказать»**.
3. Нажмите «Разрешить», если это ваш сотрудник. Он получит сообщение и сможет открыть `/start`.
4. Необработанные запросы: `/requests`. Повторный запрос после отказа возможен через 24 часа.

Можно по-прежнему попросить сотрудника отправить `/id` и выдать доступ командой `/grant 123456789`. Токен сотрудникам не нужен.

Только владелец может управлять доступом:

| Команда | Что делает |
| --- | --- |
| `/staff` | Показывает ID сотрудников |
| `/grant 123456789` | Разрешает просмотр и редактирование |
| `/revoke 123456789` | Сразу закрывает просмотр и редактирование; отменяет ожидающие личные уведомления этому сотруднику |

У всех допущенных сотрудников одинаковые права на товары. Управление доступом и подключение рабочей группы остаются у владельца. Отзыв доступа не удаляет уже полученные человеком сообщения и не исключает его из рабочей группы — при увольнении уберите его из группы отдельно.

## Как добавить товар и менять размеры

Нажмите **«Добавить товар»**, отправьте название, одно фото и размеры. Проверьте карточку и нажмите **«Сохранить»**.

| Что написать | Как бот поймёт |
| --- | --- |
| `36, 37, 38` | По одной паре каждого размера |
| `36:2, 37, 38.5:3` | Две пары 36, одна пара 37, три пары 38.5 |
| `-` при полном вводе наличия | Все размеры закончились |

Дробные размеры пишите через точку, например `38.5`. Размеров в карточке может быть до 25, количество каждого — от 1 до 9999.

В разделе **«Изменить наличие»** выберите модель:

- **Добавить размеры** — прибавляет пары к текущему количеству. Например, было `38:2`, добавили `38:1`, стало три пары.
- **Убрать размеры** — убирает все пары выбранных размеров.
- **Задать всё наличие** — заменяет весь список. Для исправления остатков напишите все оставшиеся размеры и количества. Продажи оформляйте через «Продано», чтобы они попадали в отчёты.
- **Заменить фото / Название** — меняет карточку.
- **Раздел** — бренд или тип обуви, например Nike; `-` убирает раздел.
- **Убрать товар из каталога** — скрывает модель, история остаётся в базе.

Товары без размеров видны в редактировании, но не показываются в разделе «В наличии». Кнопки открывают свежие данные; уже отправленная в переписку карточка сама не обновляется. `/cancel` отменяет несохранённый ввод. При перезапуске незавершённый ввод сбрасывается, сохранённые товары остаются.

## Продажи, возвраты и отчёты

Нажмите **«Продано»** (`/sell`), выберите модель, укажите один размер и количество (`38:2`), затем цену **за одну пару** (`1500` или `1500,50`). Нажмите «Ещё товар / размер», чтобы добавить следующую позицию. В одной продаже до 20 позиций. `/cart` открывает текущую корзину. Пока вы не нажали «Подтвердить продажу», остатки не меняются.

Если товар успел изменить другой сотрудник, продажа целиком отклоняется; соберите корзину заново по актуальным остаткам. Повторное нажатие подтверждения не создаёт вторую продажу. Суммы хранятся в целых копейках (UAH), без округления через дробные числа.

Откройте **«Продажи и возвраты»** (`/sales`) и выберите продажу:

- «Вернуть …» — выберите позицию и количество. Можно вернуть часть проданных пар, по цене исходной продажи.
- «Отменить ошибочную продажу» — восстановятся все ещё не возвращённые пары. Уже оформленные возвраты повторно не прибавляются.

Возврат товара, убранного из каталога, снова делает его видимым. Любой сотрудник с доступом может оформлять продажи, возвраты и отмены; в истории видно, кто сделал операцию.

**«Отчёты»** (`/report`) показывает день, вчера, текущую календарную неделю, месяц или выбранные даты. Пример: `/report 01.10.2026 20.10.2026`. Начальная и конечная даты включены, границы суток рассчитываются по Киеву с учётом перевода часов. Возвраты и отмены отражаются в день операции: исходная продажа остаётся в истории. Выручка в отчёте — продажи минус возвраты и отмены за выбранный период, без учёта закупочной стоимости.

По умолчанию ежедневный отчёт получает **владелец в личные сообщения**, в 21:00 по Киеву. `/report_time 21:30` меняет время, `/report_time off` отключает отправку. Отчёт за сегодня включает операции до отправки: продажи после 21:00 видны в полном отчёте за этот день на следующий день. Если бот был выключен, пропущенные отчёты ставятся в очередь после запуска. Один день повторно не отправляется; при неопределённом ответе Telegram возможен повтор сообщения.

## Поиск и разделы

`/find` — поиск; можно написать `/find Nike`, `/find 38` или `/find #12`. Поиск включает товары без остатка. `/stock` сбрасывает фильтр. `/sections` показывает бренды / типы, назначенные через «Изменить наличие → товар → Раздел». Без раздела товары тоже доступны. По умолчанию названия отсортированы по алфавиту; порядок меняется кнопкой «Сортировка» под списком.

Сводка по моделям, парам и разделам: `/summary`.

## Где будут появляться изменения

По умолчанию выбран режим **рабочей группы**:

1. Создайте закрытую группу Telegram только для сотрудников и добавьте туда бота.
2. Разрешите боту отправлять сообщения и фотографии.
3. От своего аккаунта владельца отправьте в группе **`/notify_here`**. Если ботов несколько, напишите `/notify_here@username_вашего_бота`.
4. При добавлении товара и изменении размеров бот начнёт присылать в группу фото, остатки «было / сейчас» и имя сотрудника.

Чтобы уведомления приходили каждому сотруднику отдельно, в `.env` установите **`NOTIFICATION_MODE=staff`** и перезапустите бота. В этом режиме получатели — владелец и сотрудники с действующим доступом. Каждый должен хотя бы раз открыть бота и нажать `/start`: Telegram запрещает ботам первыми начинать личную переписку.

Временные ошибки сети повторяются автоматически; очередь сохраняется после перезапуска. Постоянная ошибка (например, сотрудник заблокировал бота или группа запретила фото) отражается в `/status`. Такие сообщения не помечаются доставленными. После восстановления прав новые изменения снова отправляются; пропущенные можно посмотреть в `/history`. При сетевом обрыве во время отправки Telegram иногда может принять сообщение без подтверждения — повторная попытка может дать дубликат уведомления, но не дубликат товара.

## Ноутбук вместо сервера

Платный сервер для этого варианта не требуется. Запускайте **одну копию бота** на одном ноутбуке, подключённом к питанию и интернету. Статический IP, открытые порты и настройка роутера не нужны: бот сам получает сообщения из Telegram.

- Сотрудникам достаточно Telegram; Python устанавливается только на ноутбук, где работает бот.
- Отключите автоматический сон ноутбука, в том числе при закрытой крышке. При выключении или пропаже интернета бот недоступен до восстановления работы.
- Для обычного запуска оставляйте окно бота открытым. Для автозапуска сначала успешно запустите `START_BOT.bat`, остановите его (Ctrl+C), затем откройте **`ENABLE_AUTOSTART.bat`**. Бот запустится в фоне сейчас и после следующего **входа в эту учётную запись Windows**. При аварийном завершении повторный запуск произойдёт через 10 секунд. До входа пользователя этот вариант не запускает бота.
- **`DISABLE_AUTOSTART.bat`** останавливает фоновый запуск и удаляет задачу только для этой папки. Перед обычным запуском или обновлением отключите её. Папку после настройки автозапуска не переименовывайте; при переносе сначала отключите задачу.
- Задача использует текущую учётную запись без сохранения её пароля. На управляемом компьютере Windows может запретить создание задачи; в таком случае используйте обычный запуск. Логи фонового запуска: `data/logs`. `/status` показывает имя устройства и время работы. Папка и журнал находятся рядом с базой, если `DATABASE_PATH` отличается от стандартного.
- Не запускайте одновременно бота вручную и через планировщик. Если переносите его на другой ноутбук, сначала остановите старый экземпляр и перенесите базу.
- Фото сохраняются в Telegram, в базе хранится их `file_id`; это работает на разных устройствах с тем же ботом. При создании нового бота с другим токеном старые `file_id` переносить как универсальные фото нельзя.

## Linux и macOS

Из папки проекта:

```bash
bash start.sh
```

При первом запуске создастся `.env`. Заполните `BOT_TOKEN`, повторите запуск, узнайте `/id`, остановите бота, заполните `OWNER_ID` и запустите снова. На Debian/Ubuntu для создания окружения может понадобиться пакет `python3-venv`.

Ручной запуск с уже установленными зависимостями:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m shoe_shop_bot
```

Для постоянной работы Linux подготовлен пример [systemd-службы](deploy/shoe-shop-bot.service.example). Укажите своего пользователя и реальные пути, затем установите файл как службу. Это пример для настройки на вашем ноутбуке; текущая облачная сессия не является постоянно работающим сервером.

## Резервная копия и перенос

Копии создаются автоматически при запуске и далее раз в 6 часов, сохраняются рядом с базой в `data/backups`. Хранятся последние 28 автоматических копий; копия перед обновлением не удаляется этой ротацией. Владелец может отправить **`/backup`** и получить свежий файл прямо в Telegram. Сохраните его на другом устройстве: копия на том же диске не защищает от поломки диска.

Ручная копия из папки проекта на Windows:

```powershell
.venv\Scripts\python.exe -m shoe_shop_bot.backup
```

На Linux/macOS:

```bash
.venv/bin/python -m shoe_shop_bot.backup
```

Будет создан файл в `backups/`. Команда использует механизм SQLite backup: копия включает подтверждённые изменения, даже если бот работает и база использует WAL. Храните копию отдельно от ноутбука. База содержит данные магазина, ID сотрудников и настройки уведомлений.

Для переноса остановите старый бот, скопируйте проект и `.env` на новый ноутбук, создайте на нём папку `data` и положите копию базы под именем `shop.sqlite3` (либо используйте свой `DATABASE_PATH`). Затем установите зависимости и запустите бота на новом ноутбуке. Окружение `.venv` между компьютерами не копируйте — создайте заново. Не подменяйте базу работающего процесса и не копируйте отдельно живой `shop.sqlite3`, забыв про `-wal`.

## Проверка проекта

```bash
python -m pip install -r requirements.txt
python -m unittest discover -v
```

Тесты работают без настоящего токена и без обращений в Telegram. Они проверяют обработчики Telegram, корзину, одновременные продажи, возвраты и отмены, денежные отчёты и границы суток, перенос старой базы, поиск, разделы, запросы доступа, резервные копии, расписание и очередь уведомлений. Windows CI дополнительно проверяет реальные CMD-файлы и сценарий регистрации автозапуска. Подключение к настоящему Telegram проверяется отдельно после настройки токена.
