# Постоянный запуск на Linux-сервере

Бот может работать на удалённой виртуальной машине, пока ноутбуки владельца выключены.
Подготовленный Docker Compose сохраняет базу в отдельном томе, запускает процесс после перезапуска Docker и восстанавливает его после сбоя.

## Выбор бесплатного сервера

Один из вариантов — [Oracle Cloud Free Tier](https://www.oracle.com/cloud/free/) с виртуальной машиной, которую панель явно помечает как **Always Free eligible**.
Регистрацию и проверку банковской карты владелец проходит сам на сайте сервиса. Токен бота, платёжные данные и ключи SSH не нужно отправлять в чат или GitHub.

Перед созданием проверьте в панели, что **все** выбранные ресурсы входят в бесплатный лимит: сама машина, системный диск, сеть и IP-адрес, если он используется.
Доступность бесплатных машин зависит от региона. Пробный денежный баланс сам по себе не означает, что машина останется бесплатной после пробного периода.
Тарифы и условия следует сверить с актуальной панелью и документацией провайдера; из текущей сессии прочитать сайты хостингов не удалось.
Абсолютная гарантия «бесплатно и всегда без остановок» не предоставляется этим проектом: возможны сбои, ограничения и изменения условий провайдера.

Дальнейшие команды рассчитаны на **Ubuntu 24.04 LTS**. Подходят x86-64 и ARM64 с доступным Docker-образом Python 3.12. Передача данных и запуск выполняются после создания машины и подключения к её терминалу.

## 1. Установка Docker и получение проекта

В терминале сервера:

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2 git
sudo systemctl enable --now docker
git clone https://github.com/hanterpasa-star/Python.git ~/shoe-shop-bot
cd ~/shoe-shop-bot
sudo docker compose build
```

Виртуальное окружение `.venv` с ноутбука переносить не требуется: Python и библиотеки находятся внутри образа.

## 2. Настройки и товары с работающего ноутбука

Сначала остановите старую копию бота. После остановки сделайте резервную копию базы на Windows, выполнив из папки проекта:

```powershell
.venv\Scripts\python.exe -m shoe_shop_bot.backup
```

В `backups` появится файл базы. Перенесите его и свой рабочий `.env` на сервер через SFTP/SCP по SSH. На сервере сохраните:

- настройки — `~/shoe-shop-bot/.env`;
- копию базы — `~/shoe-shop-bot/import/shop.sqlite3`.

Используйте копию из команды backup. Она включает все подтверждённые изменения SQLite, в том числе из WAL.
Не отправляйте `.env` или базу в публичный репозиторий. При переносе того же бота сохраняются его токен, OWNER_ID, товары и список сотрудников.

В терминале сервера:

```bash
cd ~/shoe-shop-bot
chmod 600 .env
sudo docker compose create bot
sudo docker compose cp import/shop.sqlite3 bot:/var/lib/shoe-shop-bot/shop.sqlite3
sudo docker compose run --rm --no-deps --user root --entrypoint chown bot 10001:10001 /var/lib/shoe-shop-bot/shop.sqlite3
```

Эта процедура предназначена для **первого переноса в новый пустой том**. Не повторяйте копирование поверх уже работающей серверной базы. Если сервер уже содержит данные, сначала остановите его и сделайте отдельную резервную копию.

Если создаётся совершенно новый каталог, можно вместо переноса скопировать `.env.example` в `.env`, заполнить BOT_TOKEN и OWNER_ID, затем запустить бота без импорта. При таком варианте старые товары и сотрудники в новый каталог автоматически не попадут.

Путь DATABASE_PATH в Compose задаётся явно, поэтому настройки с относительным путём `data/shop.sqlite3` с Windows также подходят: сервер использует постоянный том `/var/lib/shoe-shop-bot`.

## 3. Запуск и проверка

```bash
sudo docker compose up -d
sudo docker compose logs --tail=30 bot
```

Проверьте в Telegram:

1. `/start` — меню владельца.
2. `/stock` — существующие товары и фотографии.
3. `/staff` — сохранённые сотрудники.
4. Представительное изменение товара с подтверждением и, если настроены, уведомления в рабочую группу.

Наличие запущенного контейнера само по себе не доказывает, что бот отвечает в Telegram.
После переноса оставьте одну активную копию бота: серверную. Ноутбуки сотрудников используются как обычные клиенты Telegram.

Перезапустите сервис, чтобы проверить сохранение данных:

```bash
sudo docker compose restart bot
```

Повторите `/stock` в Telegram. После успешной проверки можно выключить исходный ноутбук.
Автозапуск работает при условии, что сама виртуальная машина доступна и на ней запускается Docker. Остановка или изъятие машины провайдером требует отдельного восстановления.

## Обновление

```bash
cd ~/shoe-shop-bot
git pull --ff-only
sudo docker compose up -d --build
```

База хранится в постоянном томе `shop-data` и переживает пересоздание контейнера. Для сохранения базы используйте команды без удаления томов; `docker compose down -v` удаляет данные тома.

## Резервная копия на сервере

```bash
sudo docker compose exec bot python -m shoe_shop_bot.backup --output /var/lib/shoe-shop-bot/backups/shop-backup.sqlite3
```

Для каждой копии выбирайте новое имя: существующий файл команда не перезаписывает. Это ручная резервная копия. Автоматический график и отправка копий на другое устройство остаются отдельными пунктами плана в ROADMAP.md.
